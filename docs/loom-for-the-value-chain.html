The metaphor, spelled out once

Five parts. That is the whole vocabulary.

A loom holds threads under tension, lifts them in a set order, and passes a shuttle through the gap. Change the pattern and you weave something else on the same machine. That is the claim: one way of building, many solutions.

01 · The warp

The controls that never switch off

Four-eyes approval, an audit trail that can only be added to, data lineage, quality and security gates, data residency. The tamper-evident core runs on every pass; the rest are scoped to the risk of the change, and every skip is recorded with its reason.

Three sentences.

Stated plainly, because it earns the rest

True at every rung.

Four things that do not change

  • The cost case is directional. Output-token spend per iteration and per milestone is instrumented. Value is not — so treat any ROI number as a hypothesis until you have run one yourself.
  • The agent is itself a model. It needs ongoing validation, monitoring and independent challenge. That governance is started, not finished.
  • One greenfield domain. Legacy integration, real customer data and organisational change are where the cost actually sits, and none of it is in the curve yet.
  • Comprehension debt is the standing risk — now partly instrumented. A high or critical change cannot proceed without a comprehension record: a human-authored summary, a named non-agent owner who can explain it, challenge questions, failure modes, and reported metrics including review time and share of agent-generated code. Reported, never gated on — the objective is understanding, not throttling output. Low and medium changes carry none, so the gap is narrowed rather than closed.

Not "is it ready" — "ready for what"

Three rungs. You are already standing on the first.

Maturity here is graded on five states, and no control in the bundle is platform-enforced as shipped — every gate validates a declaration or a file. That is not a reason to wait; it is a reason to know which rung you are on, and what the next one costs.

Rung one

Before you change anything

Available now · adoption, not activation

What you can run
Internal tooling and non-customer-facing systems, on synthetic data, with no financial execution. The tamper-evident core runs on every commit; the rest are risk-scoped, with every skip recorded.
What holds it together
The harness's own discipline — hooks, reviewer agents, gates. Real, and mechanically checked.
What is still off the table
Anything where the control of record has to be the platform rather than the pipeline. The agent's restraint is not yet backed by the forge.

Rung two

After the activation runbook

A platform-admin job, not a programme

What it takes
Real CODEOWNERS teams, branch protection with no bypass, a least-privilege agent identity, vaulted secrets — then a direct-push probe that is rejected, recorded as evidence.
What it buys
The fastest credibility available: the decisions are already made, only the enforcement of record is missing. It unlocks the first two pilot stages — synthetic rehearsal, then controlled internal users on real identities. Customer exposure waits for the supervised pilot.
What is still off the table
Autonomous posting to core. Real customer data — that control surface is unbuilt.

Rung three

After the supervised pilot

Where "release candidate" comes off

What it takes
The real-PII control surface and the full register; an organisationally independent second line and model-risk function; external WORM evidence; an independent pilot report; internal-audit re-performance.
What it buys
Normal operation, and a trail you can put in front of an examiner.
What is still off the table
Nothing the method can hand you. This rung is your people and your regulator, not a bundle.

The order matters

Rung two before rung one at scale. Running a high-throughput loop on an un-activated control plane is the exact failure that produced this method's governance catalog in the first place: an agent identity merged to main because branch protection was configured but never switched on.

Three things the picture is telling you

What to notice.

Notice one

Only the middle column is authoritative

Every gate reads a file in the repository — not a Notion page, not a ticket, not a slide. Notion is where people look and Slack is where they get told; neither is what the gate looks at. When the two disagree, the repository wins, and that is deliberate: a control that reads a wiki is a control anyone can edit. Both dashed lanes are wiring you add — no Notion or Slack integration ships in the bundle.

Notice two

External systems attach through one seam

An adapter maps a system's state into a signed envelope tied to a control — GitHub branch protection and a GRC control register are the two reference mappings that ship. Swap GitHub for GitLab or ServiceNow for Archer and only the adapter changes. An adapter with no activation evidence reports as declared, not active — a wired seam, never a green control.

Notice three

Three moments need a person

Someone reacts to the prototype at stop 3, someone merges at stop 7, someone approves production at stop 8. Everything between those is the agent — and it stops at the pull request every time. Off this path there are more: a human classifies the change's risk tier, and the second line releases the hold. No agent holds any of those roles.

What would let you drop the words “release candidate”

Not more gates. Evidence from outside the repository — all five, in order.

  1. An independent pilot report, authored outside the build team, covering a supervised run end to end on a real, bounded, reversible scope — with second line watching directly rather than reading a report afterwards.
  2. Every row in the second table above exercised at least once, with its evidence retained.
  3. All material findings resolved, or formally risk-accepted by the accountable executive.
  4. Second line confirms the control set operated — not that the templates exist.
  5. Internal audit independently re-performs the evidence assessment for at least one release.

Until all five exist, the honest status is release candidate, not certified — and adopting the Loom is not, and does not substitute for, regulatory approval.

Read the gaps as carefully as the inventory

Where each role is thin.

An inventory that only lists what exists is marketing. These are the four places where a persona's support is mostly runbook rather than machinery — stated so nobody discovers it in month three.

Executive sponsor — little here runs for you personally

Five gates carry your name — production approval, readiness, the change envelope, the eval, the catalog — but they run on the engineers' pull requests, not on your desk. The instruments you hold directly are a runbook, a spend ledger, and a control catalog that cannot overstate itself. That is the honest shape of it: a bundle cannot appoint an accountable officer, convene a board, or obtain a regulator's non-objection. What it can do is make the evidence you answer with tamper-evident.

Internal audit — no place to look

You get a sealed bundle and gates you can re-run at the released commit. You do not get a read-only evidence portal — that is graded absent, and standing one up is the independent-assurance runbook's work, along with the external WORM store that makes self-assurance into examinable assurance.

Operations — the bundle does not run your pager

No SRE, observability, incident detection or on-call ships, by design. The operations-signal gate reads a JSON log; producing the signal in the first place is entirely yours. What you get is the guarantee that a signal, once logged, cannot fall on the floor untriaged — and that the log cannot stay empty once anything is in production.

Security — every scanner is a slot, not a fill

The gates validate scanner output semantically — an error-level finding blocks. You bring the SAST, SCA and image hardening; the frame gives each a named place in the line. Secret detection is the one exception: that scanner does ship, and it reads git history, so a deleted secret is still caught.

A 90-day evaluation — not the full adoption order

Ninety days.

  1. Days 1–14 · the fastest win available

    Activate the control plane

    Real CODEOWNERS teams; branch protection with required code-owner review and no bypass for anyone, including admins; a least-privilege agent identity that can push to feature/* and open pull requests but cannot merge, cannot touch settings, and holds no admin rights. Then prove it: have the agent identity attempt a direct push to main and record the rejection. This is the step that moves controls from written to enforced, and it is a platform-admin job — not the build team's, and structurally not the agent's.

  2. Days 15–30

    Mount your seams, run one discovery

    Your brand profile and your data-risk register replace the demo instances; your identity registry names who may approve what, with builders and second line disjoint. Then take one real but bounded problem through discovery end to end, to a green hand-off. A discovery that fails here is a successful discovery — it means you stopped the wrong problem for the price of a fortnight.

  3. Days 31–60

    Run the loop, and instrument it from the first commit

    Internal, non-customer-facing scope, synthetic data. Record elapsed time, people involved, human review hours and token spend from day one — see below for why. Second line embedded and watching directly.

  4. Days 61–90 · the exercise that actually decides it

    Seal a release, then have audit re-perform it

    Re-run every gate at the released commit and check the sealed bundle independently. If your internal audit function can reconstruct the release without asking the build team a single question, you have your answer. If they cannot, you also have your answer — for the price of one quarter and no customer exposure.

  5. Only then

    The supervised pilot

    Six staged cohorts, from synthetic rehearsal to normal operation, with an independent pilot report authored outside the build team. Two workstreams run alongside it and are not in the 90 days above: standing up model-risk management — the gap most specific to an AI harness — and an organisationally independent second line with external WORM evidence. That is the gate for dropping the words "release candidate", and it is months, not weeks.

The number your board will ask for

"How much faster?" — and what is honestly measurable today.

A count is not a rate. "134 of 139 stories" says nothing about speed until it has a denominator, and this method does not currently record one. Here is what exists and what does not — so your pilot produces the number instead of repeating the claim.

Instrumented
Token spend

An append-only ledger, one entry per iteration, aggregating per iteration and per milestone. It seals into the release evidence bundle — a release's cost is part of its record. Deliberately telemetry, never a merge gate.

Not captured
Elapsed time

The decision log carries per-entry timestamps, but capture is adopter wiring and nothing aggregates them per story or per milestone. Without that, throughput is a count and not a rate.

Not captured
People involved

No headcount denominator exists. "134 stories" with two engineers and with twelve are entirely different claims, and the record cannot currently tell them apart.

Partly instrumented
Human review hours

The comprehension record now reports review time, complexity and reviewer familiarity — but only for high and critical changes, and the values are reported rather than gated. Low and medium changes, which are most of them, still go uncounted.

The honest position

One and a half of four. Until the rest are recorded on a real run, "faster" is a claim and not a finding — and this page says so rather than filling the gap with a benchmark. Elapsed time and token spend are a few lines in the build loop; headcount and review hours need someone to record them, which is a process decision. Make it on day one — it is what turns a pilot into evidence.

The tripwire

Track minutes of review per pull request month over month. When throughput climbs while that number falls, four-eyes is decaying into ceremony — every gate stays green and the gap widens between the code that exists and the code a human still understands. That is the method's own named standing risk, and this is the one instrument that would catch it.
